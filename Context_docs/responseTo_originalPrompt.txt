2. The Universal Event JSON Schema
To ensure NebulaX and OrbitGuard can talk to each other, we need a strict contract. This schema is designed to handle everything from a failed SSH login to a satellite entering the horizon.

We will use a "Header/Body" structure, similar to standard IP packets.

Schema Definition (event_schema.json):
{
  "event_meta": {
    "id": "uuid-v4-string",
    "timestamp": "2025-05-21T14:30:00Z",
    "origin_module": "space.tracker | blue.honeypot | red.attack.engine",
    "event_type": "TLE_UPDATE | SSH_AUTH_FAIL | EXPLOIT_SUCCESS",
    "severity": "INFO | LOW | MEDIUM | HIGH | CRITICAL",
    "classification": "UNCLASSIFIED | SIMULATION | REAL_WORLD"
  },
  "context": {
    "related_ip": "192.168.1.50",
    "related_asset_id": "SAT-NOAA-19 | VM-UBUNTU-01",
    "mitre_attack_id": "T1110 (Optional)",
    "legal_compliance_tag": "CFAA_SAFE_HARBOR | PUBLIC_RF_DATA"
  },
  "payload": {
    "description": "Flexible object containing specific data",
    "data": {
      // This section changes based on origin_module
      // Example Space: { "azimuth": 45.2, "elevation": 12.0, "freq": "137.1MHz" }
      // Example Cyber: { "user": "root", "password_attempt": "password123" }
    }
  }
}

Why this schema works:

origin_module: Allows the UI to instantly know which widget to render.

classification: Crucial for your "Grey" research. You can tag real RF intercepts as REAL_WORLD and attacks on your sim as SIMULATION. This prevents legal confusion in your reporting.

mitre_attack_id: Instantly maps your project to industry standards.
